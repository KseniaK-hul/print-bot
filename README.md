# printbot — бот печати, версия 3

Полностью переписанная версия. Логика та же (см. `../LOGIC.md`), тексты
сохранены дословно, архитектура другая.

## Запуск

```bash
pip install -r requirements.txt
python main.py
```

Настройки берутся из `.env`.

## Тесты

```bash
python -m pytest tests -q
```

30 тестов, все проходят без Telegram и без сети. Среди них — сквозной
прогон всего диалога на заглушках (`tests/test_dialog.py`): полный путь
клиента от `/start` до заказа у админа проверяется за долю секунды.

## Где что искать при баге

| Симптом | Куда идти |
|---|---|
| Неправильная цена | `pricing/calculator.py` |
| Бот увёл не туда после вопроса | `core/flow.py` — там весь маршрут одним экраном |
| Сломался конкретный вопрос | `steps/<имя_шага>.py` — там всё про этот вопрос |
| Не тот текст / не тот язык | `texts/ru.py`, `texts/en.py` |
| Бот не реагирует на кнопку | `core/router.py`, лог покажет шаг и что пришло |
| Что-то с админ-панелью | `admin/panel.py` |
| Диалоги не закрываются / память | `tasks/janitor.py`, `core/store.py` |

Каждый апдейт оставляет в логе одну строку вида:

```
uid=1184702118 color_mode -> format
```

По ней сразу видно, где пользователь и куда пошёл.

## Три решения, на которых держится архитектура

**1. Один шаг — один файл, один класс.**
Шаг умеет только две вещи: задать вопрос (`ask`) и разобрать ответ
(`handle`). Куда идти дальше, он не решает — возвращает смысл
(`Next('A4')`), а маршрут описан в `core/flow.py`. Поэтому логику сценария
можно менять, не трогая шаги, и наоборот.

**2. Текст только по ключу.**
Внутри шага нет доступа к готовым строкам — есть `ctx.t('fold_choice')`.
Язык подставляется из сессии, выбранной на первом шаге, поэтому «русская
фраза в английском диалоге» невозможна по построению. Тест
`test_no_russian_text_inside_steps` дополнительно не даёт написать русский
текст прямо в шаге.

**3. Своё состояние вместо ConversationHandler.**
Состояние ровно одно — `session.step`. У PTB состояния и паттерны кнопок
регистрируются отдельно, и при двух десятках состояний обработчики начинают
перехватывать чужие апдейты — так появились баги «отзыв на английском не
отвечает» и «оператор не может ответить». Здесь один вход на всё:
`core/router.py`.

## Память и уборка

Одна активная сессия — примерно 3–6 КБ (страницы хранятся диапазонами
`[(1,3),(5,5)]`, а не списками номеров). Даже десять тысяч одновременных
диалогов это ~50 МБ, так что 512 МБ сервера в число заказов не упираются.

Сессия удаляется всегда одним и тем же способом — `store.drop()`, который
заодно сносит скачанные PDF. Поводов пять:

- клиент подтвердил заказ (файлы уже ушли админу, держать нечего);
- клиент отказался или написал `/cancel`;
- клиент начал новый заказ через `/start`;
- заказ брошен: 15 минут молчания → предупреждение с кнопкой «Продолжить»
  → ещё 30 секунд → диалог закрыт (`tasks/janitor.py`);
- брошена побочная сессия — чат с оператором или неоконченный отзыв: они
  закрываются молча через 30 минут, без предупреждения (терять там нечего).

### Когда заканчивается разговор с оператором

Шаг `operator_chat` возвращает `Stay()`, то есть сам себя не завершает —
без явного выхода человек остался бы в режиме оператора навсегда. Выходов
три: кнопка «🔚 Завершить разговор» у клиента, такая же кнопка у оператора
под сообщением клиента, и закрытие по молчанию через `IDLE_SIDE_SEC`.

### Незаконченный ввод админа

Нажав «❌ Отмена» или «✍️ Ответить клиенту», админ должен написать текст.
Эта заявка живёт `ADMIN_PENDING_TTL_SEC` (10 минут) и сбрасывается при
нажатии любой другой кнопки. Иначе админ, который отвлёкся на час, отправил
бы клиенту как причину отмены первое, что напишет боту потом.

При старте `tasks/tempfiles.py` подчищает папки, оставшиеся от прошлых
запусков (упавший процесс, перезагрузка сервера).

**Отдельно про «бот умирает после N заказов».** Причина была не в
количестве заказов: старый анализ цвета создавал `fitz.Pixmap` на каждую
картинку, то есть распаковывал её в сырой RGB. Скан A0 в 300 dpi — это
~400 МБ на один файл, и процесс на 512 МБ убивался от одного тяжёлого
чертежа. Теперь цвет спрашивается у пользователя, а от PDF нужно только
количество страниц (`tasks/pdf.py`) — рендеринга нет вообще.

   сейчас стоит временная защита от очевидного мусора).
4. Нужно ли больше вариантов срока и предупреждение о наценке.
5. Онлайн-оплата.

## Отладочные переменные в `.env`

Обе задавать **только локально**, в проде их быть не должно:

- `FORCE_BUSINESS_HOURS=1` — снимает проверку рабочих часов;
- `DEBUG_MODE=1` — позволяет админу проходить клиентский сценарий, получая
  при этом админские уведомления в тот же чат.
